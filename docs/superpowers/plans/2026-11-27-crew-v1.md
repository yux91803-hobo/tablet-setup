# crew 第一版：施工计划

> **给施工者（li2 上的 Antigravity）**：按任务顺序做。每一步都先写测试，跑一下看到它失败，再写实现，最后跑全部测试看到通过。每个任务做完单独提交一次。不要推送，你在 li2 上没有 GitHub 权限，也不需要；做完由复核者（Claude Code）把提交拉回去审。遇到计划和设计对不上、或者计划写错了，按设计做，并在提交说明里写清「偏离：…，原因：…」。

**目标**：做出设计里的 crew 第一版。平板上的 DSH 通过 `crew` 命令、技能「团队」和 DSH Go 插件 `liming-crew`，带 li、li2 上常驻的 Antigravity 一起干活；装机脚本改成新做法。

**结构**：
- `crew.sh` 是平板上的一个 bash 脚本，所有远端操作都走 `ib exec <机器>`，到那台去调本机的 hcom。
- 插件是 DSH Go 原生插件，在引擎里调 `crew --json` 取数据，推给面板和状态条。
- 云端准备由 `setup.sh` 的 `remote_script` 经 `ib exec --stdin` 送到每台去跑。

**技术**：bash（ShellCheck 0.11 不报警）、Node 22 的 `node:test`、DSH Go 插件 API（`ctx.dshGo.panel`、`ctx.dshGo.strip`）、hcom 0.7.31、Antigravity CLI（`agy`）。不加任何 npm 依赖。

**设计**：[`docs/superpowers/specs/2026-11-27-crew-design.md`](../specs/2026-11-27-crew-design.md)，它说了算。

- crew 的退出码：

  | 码 | 含义 |
  |---|---|
  | 0 | 成功 |
  | 2 | 用法错误 |

  | 6 | 那台没有 crew agent |
  | 7 | 现在没有等批准的操作 |
  | 8 | 等待超时 |
  | 9 | 远端出错，或者画面认不出来 |

## 重点检查（测试必须覆盖下面五类情况）

1. **站长和 DSH 打的字，经 `ib exec`、远端 bash、hcom 一路传过去不能走样**：引号、`$`、反引号、换行、中文、以 `-` 开头的文字都要原样到达。见任务 4。
2. **InstaBox 机器状态的各种值**：`running`、`suspended`、`stopped`、`starting`；`cooldownUntil` 在将来或过去；`ib get` 失败。看状态不能把机器叫醒。见任务 2。
3. **`agy` 更新后画面变了**：认不出首次设置、信任、审批或链接时，明确失败，不误按键。见任务 3、4。
4. **插件超出预算**：每次推送的数据不超过 32 KiB，每秒不超过 4 次；点按 3 秒内要返回，慢操作用延后效果。见任务 8。
5. **`crew wait` 不能留下后台任务**：一台有了结果，就杀掉其它机器上的等待；超时要退出；被中断（SIGTERM）也要清理干净，不能让机器一直醒着。见任务 5。

## 任务 2：crew 的只读部分（status、screen、log）

**文件**：
- 建：`crew.sh`、`test/crew.test.cjs`
- 改：`.github/workflows/test.yml`（ShellCheck 加 `crew.sh`）

**接口**（后面的任务和插件都靠这些）：
- 环境变量：
  - `LIMING_IB`（缺省 `ib`）；
  - `LIMING_CREW_STATE`（缺省 `$HOME/.config/liming/crew`），平板上存状态缓存、同意标记、每台看到的最后事件号。
- 远端命令统一由 `remote <机器> <bash 命令串>` 发出，实现为 `"$IB" exec "$m" --timeout <秒> -- "<命令串>"`。命令串开头加 `export PATH="$HOME/.local/bin:$PATH";`。要传用户文字时用 `--stdin`，见任务 4。
- 找 agent：在那台上跑 `hcom list --json`，取 `tag == "crew"` 而且 `status != "stopped"` 的那一个。
- `crew status [li|li2] [--json]`：
  - 不给机器就两台都看。
  - 对每台先跑 `ib get <m> --json`：
    - `state == "running"`，才去远端读 agent；
    - `cooldownUntil` 是将来的时间，记为 `cooldown`；
    - 其它状态记为 `paused` 或 `stopped`，不 exec，不叫醒；
    - `ib get` 失败记为 `unknown`。
  - `--json` 输出：
    ```json
    {"at":"<ISO 时间>","machines":[{"machine":"li2","state":"running|paused|stopped|cooldown|unknown","cooldownUntil":null,
      "agent":null|{"name":"…","status":"active|listening|blocked|…","context":"…","detail":"…","ageSeconds":0,"unread":0,"dir":"…","remoteUrl":null}}]}
    ```
  - 每次运行都把这份 JSON 写到 `$LIMING_CREW_STATE/status.json`：先写临时文件再改名。插件的状态条只读这个文件。
  - 不加 `--json` 时每台一行中文，比如 `li2：干活中（跑命令）· 2 分钟前`、`li：睡着`、`li：冷却到 21:40`。
- `crew screen <m> [--json]`：`hcom term <名字> --json`。不加 `--json` 时只打 `lines`，去掉行尾空白。
- `crew log <m> [--last N] [--since ID] [--mark] [--json]`：
  - 要的事件：这个 agent 自己的事件，加上发给它或者它发出的消息。用 `hcom events --last N`，有 `--since` 时用 `--sql "id > ID"`，具体写法以 hcom 0.7.31 实际支持的为准。
  - `--json` 原样输出 JSON 行。
  - 不加 `--json` 时每条一行中文，比如：
    - `19:38 收到 dsh：…`
    - `19:38 跑命令：hcom send …`
    - `19:38 发给 dsh：…`
    - `19:38 空闲`
  - `--mark` 时，把最后一条的事件号写到 `$LIMING_CREW_STATE/<m>.last-id`。

## 任务 5：crew wait

**文件**：改 `crew.sh`、`test/crew.test.cjs`（假 `ib` 补上 `exec --background`、`jobs wait`、`jobs logs`、`jobs kill`）

**接口**：`crew wait <m>... [--timeout 分钟]`。
- 缺省 30 分钟，最大 50 分钟。
- 每台只等这台 agent 的三种事件，并且只等事件号大于 `<m>.last-id` 的：
  - 发给 dsh 的消息；
  - 状态变成 `listening`（做完了）；
  - 状态变成 `blocked`（卡住了）。
- 实现：每台用 `ib exec --background <m>` 在远端跑 `hcom events --wait <秒> …过滤…`，拿到任务号；然后用 `ib jobs wait <m> <任务号>` 等它结束。几台一起等。
- 结果：
  - 第一台等到了：打印一行 JSON `{"machine":"li2","event":{…hcom 的那条事件…}}`，把 `<m>.last-id` 更新到这条事件，用 `ib jobs kill` 结束其余机器上的等待，以 0 退出。
  - 超时：结束所有等待，以 8 退出。
  - 收到 SIGTERM 或 SIGINT：结束所有等待后退出。
- 机器在冷却就不等它；要等的机器全在冷却，以 5 退出。

- [ ] **写失败测试**：
  - `一台发来消息就结束，打印那条事件，并更新 last-id`
  - `一台结束后会 kill 另一台的等待任务`
  - `超时以 8 退出，并 kill 所有等待任务`
  - `收到 SIGTERM 会 kill 所有等待任务`
  - `已经看过的事件（id 不大于 last-id）不算`
  - `全部在冷却以 5 退出`

  运行后预期全部失败。

  - `dshGo`：`v: 1`，`title` 为 `{zh:"团队", en:"Crew"}`，`icon: "robot"`，`contributes` 为：
    ```json
    {"composer.strip":[{"id":"crew-strip","icon":"robot","panel":"crew"}],
     "panels":[{"id":"crew","title":{"zh":"团队","en":"Crew"},"icon":"robot","placement":["features","chat.panel"]}]}
    ```
    字段写法以 DSH Go 文档为准，自查工具说了算。

  - `export async function runCrew(args: string[], {timeoutMs, stdin?, signal?}) → {code, stdout, stderr}`：用 `node:child_process` 调 `crew`，`LIMING_CREW_BIN` 可以覆盖路径。
  - `export async function crewJson(args, opts) → object|null`
- `lib/views.js`（纯函数，不碰进程和文件）：
  - `export function stripText(status) → string`：不超过 24 个字。比如：
    - 一台干活、一台闲着：「li 干活中 · li2 空闲」
    - 都睡着：「li、li2 都在睡」
    - 读不到：「团队：未知」
  - `export function panelView(caps) → view`：根节点 `stack`，`v: 2`。内容：
    - 成员区：每台一行，写状态和多久以前；
    - 机器选择（`options`）；
    - 现场区：最近动作用 `list` 或 `steps`，画面要点用 `text`；
    - 输入表单（插话）；
    - 按钮：「叫停」「网页」，等审批时再加「允许」「拒绝」。
    - 数据全部用绑定从推送的数据里取。
  - `export function panelData({status, selected, screen, log}) → object`：
    - 画面只取最后 12 行有内容的行；
    - 动作只取最后 15 条，每条不超过 120 个字；
    - 整体 `JSON.stringify` 后不超过 30 KiB，超了就继续截短。
  - `export function nowAgo(seconds) → string`：例如「刚才」「2 分钟前」。
- `lib/index.js`：`export const name = 'liming-crew'`，在 `apply(ctx)` 里 `ctx.inject(['dshGo'], …)`。

  - **面板**：
    - `data(scope, emit)` 在面板打开期间每 3 秒取一次：`crew status --json` 加选中那台的 `crew screen <m> --json` 和 `crew log <m> --last 15 --json`；
    - 上一次还没取完就跳过这一轮；
    - 返回清理函数，面板关上就停。
  - **点按**：
    - 「插话」：先回 `pending`，再 `crew send <m> --stdin`，结果用 `toast` 告知。慢操作一律用延后效果，因为点按要在 3 秒内返回。
    - 「叫停」：`crew stop`。
    - 「允许 / 拒绝」：`crew approve`。
    - 「网页」：返回 `{link: remoteUrl}`，没有链接时 `toast`「这台还没有网页链接」。
    - 「切换机器」：`patch` 选中的机器。
